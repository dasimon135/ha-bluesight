# BlueSight v1.5 — ESPHome Telemetry Component Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Give BlueSight evidence Home Assistant cannot supply — real SMP pairing failures, the proxy's NVS bond list, and per-connection idle time — turning storm detection from a heuristic into a measurement and closing the ghost-slot gap for BLE devices HA does not manage.

**Architecture:** A passive ESPHome component observes the same Bluedroid GAP/GATTC events `bluetooth_proxy` sees and publishes three bounded text sensors of *facts*. The Home Assistant side finds those entities through the device registry, parses them in a pure module, and feeds the existing detectors. Every threshold lives on the HA side; the firmware holds none.

**Tech Stack:** Python 3.14, Home Assistant 2026.8, `habluetooth` 6.x, ESPHome 2026.2+ (ESP-IDF, Bluedroid), pytest.

**Ships as 0.6.0.** The milestone is named v1.5 throughout because it was scoped under that name; internationalisation was then resequenced ahead of it and took 0.5.0.

**Design doc:** `docs/plans/2026-08-24-v1.5-esphome-component-design.md` — read it first. It records why the roadmap's NimBLE premise was wrong and why the evidence must be collected in firmware.

```python
"""Pure parser for the telemetry the BlueSight ESPHome component publishes.

No Home Assistant dependency; fully unit-testable with plain pytest.

The firmware publishes facts, never verdicts, in three bounded strings (see
``docs/plans/2026-08-24-v1.5-esphome-component-design.md``). This module turns
those strings into typed structure and nothing more: every threshold and every
judgement lives in the detectors, where pytest can reach it and where a retune
needs no reflash.

The addresses arrive as compact 12-character hex, because Home Assistant caps
an entity state at 255 characters and dropping the colons is what keeps a full
bond list inside that cap. They are expanded here so they correlate with the
habluetooth addresses the rest of BlueSight speaks.
"""
from __future__ import annotations

from dataclasses import dataclass

from .model import normalize_address

#: States that mean "this proxy is not talking to us right now". They must map
#: to None rather than an empty reading: a rebooting proxy drops its ESPHome
#: entities to `unavailable`, and reporting zero SMP failures at exactly the
#: moment a proxy is in trouble would be a lie.
_NO_SIGNAL = {"unavailable", "unknown", "none", "restored"}


def expand_compact_mac(raw: str) -> str:
    """Turn ``d0cf130ec92a`` into ``D0:CF:13:0E:C9:2A``.

    An already-expanded address passes through, so the parser tolerates a
    firmware build that decides to send colons.
    """
    text = raw.strip()
    if ":" in text:
        return normalize_address(text)
    if len(text) != 12:
        raise ValueError(f"not a compact MAC: {raw!r}")
    pairs = [text[i : i + 2] for i in range(0, 12, 2)]
    return normalize_address(":".join(pairs))


def _split(raw: str | None) -> list[str] | None:
    """Return the comma-separated fields, or None when there is no signal."""
    if raw is None:
        return None
    text = raw.strip()
    if text.lower() in _NO_SIGNAL:
        return None
    if not text:
        return []
    return [field for field in text.split(",") if field.strip()]


def parse_addresses(raw: str | None) -> set[str] | None:
    """Parse a plain address list (the bond list)."""
    fields = _split(raw)
    if fields is None:
        return None
    out: set[str] = set()
    for field in fields:
        try:
            out.add(expand_compact_mac(field))
        except ValueError:
            continue  # firmware is the least trustworthy input; skip, never crash
    return out


def _parse_mapping(raw: str | None, cast) -> dict | None:
    fields = _split(raw)
    if fields is None:
        return None
    out: dict = {}
    for field in fields:
        address, _, value = field.partition(":")
        if not value:
            continue
        try:
            out[expand_compact_mac(address)] = cast(value)
        except ValueError:
            continue
    return out


def parse_counts(raw: str | None) -> dict[str, int] | None:
    """Parse ``MAC:count`` pairs (the SMP failure counters)."""
    return _parse_mapping(raw, int)


def parse_idle_seconds(raw: str | None) -> dict[str, float] | None:
    """Parse ``MAC:seconds`` pairs (per-connection time since GATT traffic)."""
    return _parse_mapping(raw, float)


@dataclass(frozen=True, slots=True)
class ProxyTelemetry:
    """One proxy's telemetry snapshot. ``None`` means the signal is absent."""

    source: str
    smp_failures: dict[str, int] | None = None
    bonds: set[str] | None = None
    slot_idle_seconds: dict[str, float] | None = None

    @property
    def has_signal(self) -> bool:
        """True when at least one of the three sensors is reporting.

        Drives the per-proxy choice between SMP evidence and the heuristic.
        """
        return any(
            v is not None
            for v in (self.smp_failures, self.bonds, self.slot_idle_seconds)
        )
```

```python
class CounterDeltas:
    """Turn per-proxy monotonic counters into per-snapshot event counts.

    Stateful across snapshots but pure: no clock, no I/O, no Home Assistant.

    Two rules carry the weight:

    * The first reading only establishes a baseline. The counter has been
      climbing since the proxy booted, possibly for weeks; replaying that
      history as fresh failures would open a storm incident on startup.
    * A decrease means the proxy rebooted, not that anything recovered. The
      baseline rearms at the new value and nothing is counted, so the climb
      back up is not counted a second time.
    """

    def __init__(self) -> None:
        self._baseline: dict[str, dict[str, int]] = {}

    def update(
        self, source: str, counts: dict[str, int] | None
    ) -> dict[str, int]:
        """Advance one snapshot for ``source``; return new events per address.

        ``counts`` of None means the telemetry is absent this snapshot. The
        baseline is deliberately kept rather than dropped: a proxy that blips
        unavailable would otherwise replay its entire counter on return.
        """
        if counts is None:
            return {}
        previous = self._baseline.setdefault(source, {})
        new_events: dict[str, int] = {}
        for address, current in counts.items():
            before = previous.get(address)
            if before is not None and current > before:
                new_events[address] = current - before
            previous[address] = current
        return new_events

    def forget(self, source: str) -> None:
        """Drop a retired proxy's baselines (pairs with ``forget_proxy``)."""
        self._baseline.pop(source, None)
```

```python
@dataclass(frozen=True, slots=True)
class Incident:
    kind: IncidentKind
    address: str
    sources: list[str] = field(default_factory=list)
    detail: str = ""
    #: How this incident was observed: "smp" when the ESPHome telemetry
    #: component supplied real SMP evidence, "heuristic" when it was inferred
    #: from slot releases. Deliberately absent from `key`: the same physical
    #: fault is one incident however it was seen, so a proxy switching between
    #: the two must not raise a second alert for a fault that never stopped.
    evidence: str = "heuristic"

    @property
    def key(self) -> str:
        return f"{self.kind.value}:{self.address}:{','.join(sorted(self.sources))}"
```

```python
def detect_bond_lost(
    telemetry: list[ProxyTelemetry], names: dict[str, str]
) -> list[Incident]:
    """A device whose pairing keeps failing on a proxy that holds no bond for it.

    This is the one diagnosis that needs the firmware: Home Assistant can see
    neither SMP failures nor the proxy's NVS bond store. Both halves are
    required, and both must be *reported* -- an absent bond list cannot
    distinguish "no bond" from "not told", so it yields nothing rather than a
    confident wrong answer.

    The remedy is exact and worth stating: re-pair through this specific proxy,
    not whichever one Home Assistant happens to pick next.
    """
    out: list[Incident] = []
    for tel in telemetry:
        if tel.smp_failures is None or tel.bonds is None:
            continue
        name = names.get(tel.source, tel.source)
        for address, count in sorted(tel.smp_failures.items()):
            if count <= 0 or address in tel.bonds:
                continue
            out.append(Incident(
                IncidentKind.BOND_LOST, address, [tel.source],
                detail_key="incident.bond_lost.detail",
                detail_params={"count": str(count), "proxy": name},
                evidence="smp"))
    return out
```

```python
def detect_idle_slots(
    telemetry: list[ProxyTelemetry],
    managed_addresses: set[str],
    threshold_s: float,
    names: dict[str, str],
) -> list[Incident]:
    """A slot held with no GATT traffic, for a device Home Assistant cannot judge.

    ``detect_ghost_slots`` decides from entity availability, which only works
    for devices in the registry; an unmanaged peripheral is conservatively
    treated as alive there (see ``availability.py``). The firmware sees the
    connection itself, so it can measure silence directly.

    Managed addresses are deliberately skipped: the entity-based verdict is the
    more semantic signal, and two detectors firing on one address would
    double-report a single stuck slot.
    """
    out: list[Incident] = []
    for tel in telemetry:
        if tel.slot_idle_seconds is None:
            continue
        name = names.get(tel.source, tel.source)
        for address, idle in sorted(tel.slot_idle_seconds.items()):
            if address in managed_addresses or idle <= threshold_s:
                continue
            out.append(Incident(
                IncidentKind.GHOST_SLOT, address, [tel.source],
                detail_key="incident.ghost_slot.idle_detail",
                detail_params={"proxy": name, "seconds": str(int(idle))},
                evidence="smp"))
    return out
```

```python
"""Isolated Home Assistant surface for the BlueSight ESPHome telemetry.

The twin of :mod:`.adapter`: this is the ONLY module that knows how the
telemetry reaches Home Assistant, so a change in that surface touches one file.

Discovery matches on the entity registry's ``original_name``. Not
``entity_id`` -- users rename those. Not ``unique_id`` -- that is the ESPHome
integration's internal format, and coupling to another integration's
implementation detail is what this architecture exists to avoid. Our own
component names these sensors in codegen, so the name is ours and it is stable.
"""
from __future__ import annotations

import logging
from collections.abc import Callable
from typing import Any

from .telemetry import ProxyTelemetry, parse_addresses, parse_counts, parse_idle_seconds

_LOGGER = logging.getLogger(__name__)

#: Sensor names the ESPHome component publishes. These are the data contract:
#: change one and every already-flashed proxy goes dark.
SMP_NAME = "BlueSight SMP failures"
BONDS_NAME = "BlueSight bonds"
SLOTS_NAME = "BlueSight slots"


def read_proxy_telemetry(
    source: str,
    device_id: str,
    entries_for_device: Callable[[str], list[Any]],
    state_of: Callable[[str], str | None],
) -> ProxyTelemetry:
    """Read one proxy's telemetry, tolerating a proxy that has none.

    Callables are injected rather than imported so this stays unit-testable
    without a running Home Assistant. Every failure mode -- no component, a
    partial flash, an unreadable registry -- lands on ``None`` for the affected
    signal, never on a zero that would read as "nothing wrong".
    """
    try:
        entries = entries_for_device(device_id) or []
    except Exception:  # a broken lookup must not blank the whole snapshot
        _LOGGER.debug("Telemetry lookup failed for %s", source, exc_info=True)
        return ProxyTelemetry(source)

    raw: dict[str, str | None] = {}
    for entry in entries:
        name = getattr(entry, "original_name", None)
        if name in (SMP_NAME, BONDS_NAME, SLOTS_NAME):
            raw[name] = state_of(entry.entity_id)

    return ProxyTelemetry(
        source=source,
        smp_failures=parse_counts(raw.get(SMP_NAME)),
        bonds=parse_addresses(raw.get(BONDS_NAME)),
        slot_idle_seconds=parse_idle_seconds(raw.get(SLOTS_NAME)),
    )
```

Registering the GATTC handler unconditionally would fail to compile on a scan-only node, so codegen guards it on `"esp32_ble_tracker" in CORE.loaded_integrations` and the C++ guards the matching code on `USE_ESP32_BLE_CLIENT`.
  - The substance of the design finding is unchanged and was re-verified: `ESP32BLE::gap_event_handler` enqueues `ESP_GAP_BLE_AUTH_CMPL_EVT` (`ble.cpp:639`), `BLEEvent::init_gap_data_` `memcpy`s the **entire** `esp_ble_sec_t` union (`ble_event.h:352`), and `ble.cpp:524` calls every registered handler. `auth_cmpl.{bd_addr,success,fail_reason}` arrive intact. Likewise every GATTC event is enqueued (`ble.cpp:693`) with the full param union copied (`ble_event.h:383`).
  - Handlers run on the ESPHome main loop, not the Bluetooth task: events are queued first. Publishing from inside a handler is safe.
- **Never** open a connection, write a bond, or call into `bluetooth_proxy`. The read-only invariant holds into the firmware.
- Count SMP failures from `ESP_GAP_BLE_AUTH_CMPL_EVT` where `param->ble_security.auth_cmpl.success` is false, keyed by `bd_addr`. Cap at 8 addresses (drop the least recently updated) so the state stays under 255 characters.
- Read bonds with `esp_ble_get_bond_device_num()` / `esp_ble_get_bond_device_list()`. Verified against ESP-IDF 5.5.2: `esp_ble_get_bond_device_num()` returns `ESP_FAIL` (-1) while Bluedroid is disabled, and `esp_ble_get_bond_device_list()` treats `*dev_num` as a hard buffer cap (`btc_ble_storage.c:964`), so passing a smaller buffer is safe. `CONFIG_BT_SMP_MAX_BONDS` defaults to 15 (range 1..32).
  - **Never truncate the bond list.** A truncated list is not a smaller answer, it is a wrong one: an address that is bonded but cut off reads as unbonded, which is precisely the input BOND_LOST fires on. Above the cap the sensor is left unpublished (→ `unknown` → absent), which suppresses BOND_LOST rather than triggering it. Only reachable with a non-default `CONFIG_BT_SMP_MAX_BONDS`.
- Track per-connection last-traffic time from GATTC connect/disconnect/notify/read/write events; publish `MAC:idle_secs`. Note (verified in `esp_gattc_api.h`): `read` and `write` event params carry **no `remote_bda`**, only a `conn_id`, so the address has to come from a map built on CONNECT/OPEN. `conn_id` is unique only within one GATT client interface and every client's events are fanned out to us, so the key is `(gattc_if << 16) | conn_id`.
  - Publish on slot open/close only, not on notify/read/write. Those merely reset an idle timer, and a chatty notifier would otherwise push a state over the API several times a second for a value the 60 s tick reports just as truthfully.
- **Wire format — every value must match this grammar exactly.** `telemetry.py` validates strictly, and the two failure modes differ. A *partial* mismatch is quiet: the offending field is debug-logged and dropped, so the reading silently loses entries. A *total* mismatch — every field rejected — logs a warning and reports the reading as **absent** rather than empty, because an empty reading would assert the proxy has nothing to report, which is the opposite of what is known. Each sensor publishes a `,`-separated list; an empty string means "reporting, zero entries".
  - **Address:** exactly `[0-9a-f]{12}`, or the colon-expanded form. **Not `esphome::format_hex_pretty()`** — it emits `D0.CF.13.0E.C9.2A`, dot-separated, which every address parser rejects. It is the obvious-looking helper and it is the wrong one. Use `esphome::format_hex(bd_addr, 6)` or `str_sprintf("%02x%02x%02x%02x%02x%02x", ...)`.
  - **Counts:** `[0-9]+`. No sign, no `_`, no `.`, no exponent.
  - **Seconds:** `[0-9]+` or `[0-9]+.[0-9]+`, digits required on both sides of the dot. **Never `%g` or `%e`.** `%g` switches to exponent form at 1e6, which is 11.6 days — entirely reachable for a bonded slot that never sees traffic, so it is correct on the bench and wrong in production. Any `%.Nf` is safe; prefer `"%.1f"` over `std::to_string`, which burns six decimals against the 255-character cap for no information.
  - **Pair fields** split on the *last* colon, so the value may not contain one.
  - Compute idle deltas in `uint32_t` (rollover-safe) and cast to float only afterwards — a negative value is rejected, and `(int32_t)(millis() - last)` goes negative after the 49.7-day rollover.
- The sensor names **must** match `telemetry_reader.py` exactly: `BlueSight SMP failures`, `BlueSight bonds`, `BlueSight slots`. Name them in codegen so the user never writes them — and go one step further: the schema *rejects* any other name with an explanation, because a rename is a one-line YAML change that produces a proxy which flashes, boots and reports cleanly while being invisible to Home Assistant. That failure has no symptom to follow, so it is refused where the message can say why.
- Prefer plain `snprintf` over ESPHome's formatting helpers for the three payloads. `format_hex`/`str_sprintf` moved to `alloc_helpers.h` in this release cycle and `format_hex_to` is newer still; libc's `%02x` and `%u` are the same in every ESPHome version, and this is the one place where a helper moving under our feet costs the entire data contract.
- Print idle seconds as two `%u` fields (`secs.tenths`) rather than any float format. It is not merely safe from `%g`, it is *structurally incapable* of an exponent, a sign or a NaN, and it needs no float at all.
- Publish on change plus a slow periodic refresh (60 s) so idle time advances.
